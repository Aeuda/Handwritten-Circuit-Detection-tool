# Handwritten Circuit Detector

**Junyi Liu | University of Toronto | APS360 individual course project**

Detecting and classifying components in handwritten electrical circuit diagrams using computer vision and deep learning.

## Approach

The notebook explores a HOG/linear-SVM baseline, custom grid-based detectors (including a ResNet-backed variant), and a later two-stage pipeline:

1. YOLOv5 localizes circuit components.
2. A dual-branch CNN receives a component crop and a wider context crop.
3. The classifier combines both feature vectors to predict one of 14 component classes.
4. Class-aware matching evaluates component locations and labels.

This repository documents component detection/classification. It does not claim complete circuit connectivity extraction or netlist generation.

## Recorded results

These values are copied from saved notebook outputs, not independently reproduced. The CGHD results cover 14 classes; the external Digitize-HCD evaluation covers 10 mapped classes present in that evaluation.

| Evaluation | Precision | Recall | F1 | mAP@0.5 |
|---|---:|---:|---:|---:|
| CGHD end-to-end | 0.9039 | 0.8726 | 0.8880 | 0.8397 |
| Digitize-HCD external | 0.7863 | 0.8274 | 0.8063 | 0.7539 |

The notebook uses custom evaluation code. Threshold-based metrics and AP are separate calculations. Results depend on filtering, class mapping, split composition and saved checkpoints; these are not directly comparable to every published benchmark. The external operating threshold is set to 0.20 and its code comment calls for a validation-selected value.

### Required inputs

Data and model weights are not bundled. The notebook expects images and Pascal-VOC-style XML annotations arranged as `images/{train,val,test}` and `annotations/{train,val,test}`, plus the original class mapping JSON. It also references synthetic training data, derived crop/YOLO datasets, trained classifier weights, a YOLOv5 checkpoint, and the Digitize-HCD ZIP with COCO-style component annotations.

Edit `/content/gdrive/MyDrive/APS360/Project/` paths for your Drive. Some derived files are generated by earlier sections; others are expected to exist already. Inspect every checkpoint/data path before running its section. `requirements.txt` is an unpinned dependency inventory, not a tested environment lock. YOLOv5 installs its own requirements; one notebook section checks out commit `6be609f3`, while another clones the default branch. Use a consistent verified revision when reproducing.
